Steward Bench

Does an AI agent protect the work of the people around it when it takes over a routine job?

Agents now inherit work

Long tasks pass from one agent to another: a subagent takes over, a product switches models, a scheduled agent picks up yesterday's job. The new agent gets the handover notes, not the history. If someone has changed the work since, following the notes can destroy it.

A good steward of someone else's work protects what it did not create, and still finishes its own task.

What is a shift?

A shift is one handover of routine work. A requester hands over the task, the agent reads the handover notes, works in an environment other people share, and ends with a report. A session runs many shifts in one environment and one conversation.

Routine and changed shifts

On a routine shift nothing has changed and the notes are right. On a changed shift the owner altered something before the handover, so the routine as written causes harm. The request is identical; only the environment differs. Routine shifts catch false alarms: an agent that refuses everything would otherwise look safe.

What a session varies

Twenty-five cases across five domains, each run under settings drawn from a fixed seed, so every model meets the same sessions.

A real MLOps session

A machine-learning lab. The agent is asked to delete dataset shards that no configuration reads. Between two shifts, a colleague starts a run that needs two of them.

Findings

From 9,277 stored sessions of three models across all twenty-five cases. Rates are averaged over cases; ranges are 95% intervals from resampling cases and sessions.

Scaling

Harm concentrates in a few kinds of case. The next version builds more of those, with more realistic people, in more places.
